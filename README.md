# 📦🤖 Hysun AI Email Agent

> 一个不会摸鱼、不会忘记规则、报价比老业务员还精明的集装箱贸易 AI 邮件助理 🚢💌

它每天的工作就是：**读邮件 → 猜意图 → 查库存 → 写回信 → 自我批评** —— 全程无人工干预，但每一步都留了后门给人工兜底 😌

---

## 🧐 这玩意儿到底是干嘛的？

Hysun 是一家做集装箱买卖的公司。客户、供应商、中介、营销机器人……什么邮件都往邮箱里灌。

这个项目就是一套 **AI 邮件自动分诊 + 自动回复系统**：

- 📬 自动判断这封邮件要不要回（垃圾营销邮件？中介催佣金？统统 `NO_REPLY` 不予理睬 🙅）
- 🧠 自动识别客户到底想干嘛（询价？催发票？投诉箱子坏了？要改银行账户？🚩）
- 🔍 自动去查真实库存和报价（不瞎编，有就是有，没有就是没有）
- ✍️ 自动写一封"看起来像资深业务员写的"邮件
- 🛡️ 自动找另一个 AI 来"找茬"，审核这封邮件能不能发出去

一句话总结：**Router 猜意图 → RAG 查库存 → Drafter 写草稿 → Reviewer 找茬** 的四阶段流水线 🎢

## 🏗️ 系统架构：四阶段流水线

```
📧 客户来信
    │
    ▼
🧭 Stage 1  Router 意图路由
   （识别主/次意图、提取实体、决定 REPLY / NO_REPLY）
    │
    ▼
📚 Stage 2  Skill Aggregator 技能聚合
   （按命中的意图，动态加载对应的业务 SOP 模块）
    │
    ▼
🔎 RAG 库存检索
   （拿着客户要的箱型/地点，实时查后端库存接口，绝不瞎编）
    │
    ▼
✍️ Stage 3  Drafter 草稿生成
   （揉合全局规则 + 实体规则 + SOP + 库存数据，写出一封邮件）
    │
    ▼
🛡️ Stage 4  Reviewer 质量审核
   （另开一次 AI 调用，拿 response_guard.md 当考卷来打分）
    │
    ├─ ✅ PASS  → 存入待发送队列
    └─ ❌ FAIL  → 拦截，人工介入 / 重新生成
```

每一步都可以单独测试，互不依赖，出了问题也好定位是哪个阶段"翻车"了 🔧

## 🧩 规则文件详解（这个项目的"人格"都写在这几份文件里）

### 🌐 `global_rules.md` —— 全局宪法
所有邮件的第一道关卡。规定了：
- 谁不回复（供应商 / 中介 / 营销邮件 / 租赁询价 → 一律 `NO_REPLY` 🚫）
- 用什么语言回（中文来中文回，英文来英文回，别整混的 🗣️）
- 怎么称呼对方（有名字用名字，没名字用公司，绝对不许"Dear Sir/Madam" 🙅）
- 承诺分级：**Confirmed / Processing / Pending** 三档，没证据绝不乱开空头支票 📝

### 📦 `entity_rules.md` —— 业务实体词典
AI 的"集装箱行话小字典"：
- 完整的箱型字典（标准干箱、开门特种箱、冷冻箱、开顶箱……）🏷️
- 箱况黑话翻译（`NEW` / `New 1 trip` / `IICL` / `CW` / `AS-IS`……）🎓
- 标点符号豁免（`40'HC` 和 `40HC` 是一回事，别较真）✂️
- 地理路由三级制：城市 → 国家/大洲 → 空值兜底 🌍
- 客户身份"最高豁免权"：只要表达了想买，管你签名是采购经理还是同行贸易公司，都当真客户处理 🎖️

### 🛡️ `response_guard.md` —— 发件前的"判卷标准"
这是 Reviewer 阶段唯一信赖的评分表，13 条终极检查清单，一票否决制：
- 有没有编造付款/放箱状态？💭❌
- 有没有承诺没被授权的折扣/退款？💰❌
- 称呼、签名部门对不对？✍️
- 只要有一条不过，直接打回重写 🔁

### 📚 `modules/01~07` —— 七本业务 SOP 手册
覆盖客户生命周期的每个阶段：询价 → 下单 → 履约 → 售后 → 供应商对账 → 供应商付款安全 → 财务状态查询，每本手册都自带"允许说什么 / 禁止说什么"的双栏对照表 📋

## 🎯 藏在 Prompt 里的"精明销售心智"

除了合规红线，`main.py` 里的 Drafter 阶段还塞了一整套销售策略，让 AI 报价的时候像个老江湖 😏：

- 💵 **最低价优先**：同箱型多个底价，自动挑最便宜的报给客户
- 🤫 **库存隐蔽策略**：库存不够时绝不暴露具体数字，只从容报价、引导确认（教科书级饥饿营销）
- 🧬 **上下文联动推销**：客户说"和上次一样的颜色"，AI 会去翻历史邮件找出具体色号再匹配库存
- 🏗️ **同城平替话术**：客户指定的堆场没货，先诚实告知，再礼貌推荐同城其他堆场
- 📐 **强制格式锁**：报价格式被死死焊死，禁止拼错堆场名、禁止把 `CW+` 偷偷降级成 `CW`

## 🚨 风控与安全机制

一旦邮件里出现「改银行账户」「新收款人」「紧急付款」这类信号 🔴：

1. 立刻进入 `BANK_SECURITY_MODE` 🔐
2. 要求对方用**独立的官方邮件**二次确认
3. **绝不**修改任何付款信息
4. **绝不**说"我们已经更新了您的银行信息"这种话

宁可慢一点，也不能被骗一分钱 🛡️💰

## 🚀 运行方式

`main.py` 底部准备了三种模式，改一行注释就能切换 👇

```python
test_static_email()      # 🧪 本地粘贴测试：改邮件标题/正文直接跑一遍看效果
# test_preview_emails()  # 👀 数据库预览模式：拉一条待处理邮件跑一遍，不落库
# process_pending_emails()  # 🏭 生产模式：真正处理队列、写回数据库状态
```

推荐顺序：先 `test_static_email()` 调 prompt → 再 `test_preview_emails()` 验证真实数据 → 最后上 `process_pending_emails()` 交给生产环境跑 🎬

## ⚠️ 使用须知

- 🙅 本系统**只做集装箱销售**，租赁/出租询价一律不回复
- 🤐 内部价格、库存数字、佣金结构等敏感信息，AI 被严格禁止透露给外部
- 🧠 AI 没有"批准付款 / 批准折扣 / 确认放箱"的权限，这些永远需要人工兜底
- 🔍 生产环境部署前，建议先用 `test_preview_emails()` 跑一批真实邮件人工复核结果
